# Roadmap Nexory

Планы развития продукта. Пункты не привязаны к срокам — порядок отражает приоритет.

## Ближайшее

### Покупка билетов внутри приложения
Сейчас организатор платного мероприятия указывает **ссылку на покупку билета**
(поле «Где купить билет»), и пользователь уходит на внешний сайт.

Цель — оставить весь путь внутри Nexory:

- выбор количества билетов и оплата на экране мероприятия, без перехода в браузер;
- электронный билет в профиле пользователя (QR-код для входа на мероприятие);
- список проданных билетов и выручка в кабинете организатора;
- возвраты и отмена мероприятия с автоматическим возвратом средств.

**Что нужно для этого:**
- платёжный агрегатор с поддержкой маркетплейс-схемы (расчёты с организаторами),
  а не только приём переводов — текущая схема с прямой ссылкой на банк для этого
  не подходит;
- регистрация юр. лица или ИП у владельца сервиса;
- онлайн-касса и фискализация чеков (54-ФЗ);
- договор-оферта между сервисом, организатором и покупателем.

**Промежуточный шаг:** поле `ticket_url` уже есть в модели мероприятия
(миграция `014_event_ticket_url.sql`), так что переход на внутреннюю покупку
не потребует ломать существующие данные — внешняя ссылка останется запасным
вариантом для организаторов без подключённого приёма платежей.

## Технический долг

- Инструментальные UI-тесты (`androidTest`) на критичные сценарии: согласие →
  регистрация → создание мероприятия → удаление аккаунта.
- Тесты бэкенда с реальной БД (testcontainers): сейчас покрыты только валидация,
  коды ответов и отдача юр. документов.
- Crashlytics для сбора падений у реальных пользователей.
- Профилирование памяти и расхода батареи при активном WebSocket.
