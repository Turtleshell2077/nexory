## 2. Data Safety / Сведения о безопасности данных

Заполнять в Google Play Console → App content → Data safety.
Ниже — готовые ответы, соответствующие фактическому поведению кода.

### 2.1. Общие ответы

- **Собирает ли приложение данные пользователя?** Да.
- **Шифруются ли данные при передаче?** Да — *после перевода API на HTTPS.*
  **Пока сервер работает по http, честный ответ «нет», и это повод для отказа.**
- **Может ли пользователь запросить удаление данных?** Да, из приложения.
- **Используются ли данные для рекламы?** Нет.
- **Продаются/передаются ли данные третьим лицам?** Передаются только поставщикам
  инфраструктуры (FCM для доставки уведомлений). Не продаются.

### 2.2. Таблица данных

| Категория | Тип | Собирается | Передаётся 3-м лицам | Обязательно | Зачем |
|---|---|---|---|---|---|
| Личные данные | Email | Да | Нет | Да | Аккаунт, вход, восстановление пароля |
| Личные данные | Имя (отображаемое) | Да | Нет | Нет | Отображение профиля |
| Личные данные | Никнейм (User ID) | Да | Нет | Да | Идентификация, поиск людей |
| Личные данные | Телефон | Да | Нет | Нет | По желанию в профиле, приватность настраивается |
| Личные данные | Возраст, город, страна, «о себе», увлечения | Да | Нет | Нет | Заполнение профиля, подбор по интересам |
| Фото и видео | Фото | Да | Нет | Нет | Аватар профиля, обложка мероприятия |
| Сообщения | Сообщения в приложении | Да | Нет | Нет | Работа чатов |
| Действия в приложении | Созданные мероприятия, участия, друзья | Да | Нет | Нет | Основная функциональность |
| Идентификаторы устройства | Токен FCM | Да | **Да** (Google FCM) | Нет | Доставка push-уведомлений |
| Журналы / диагностика | IP-адрес, время запроса | Да | Нет | Да | Защита от атак и подбора паролей |
| Данные аутентификации | Пароль | Да | Нет | Да | Хранится только как bcrypt-хэш |

### 2.3. Что явно НЕ собирается

Отметить в анкете как «не собирается»:
точная/приблизительная геолокация, контакты, календарь, SMS, звонки,
история браузера, установленные приложения, состояние здоровья, фитнес,
финансовая информация и платёжные данные, биометрия, аудио, музыка.

### 2.4. PIN-код

PIN хранится **только на устройстве** (SHA-256 в DataStore) и не отправляется на сервер,
поэтому в Data Safety он **не заявляется как собираемые данные**.

## 3. Известные блокеры и незакрытые пункты

### 3.1. Блокер для Google Play: HTTP вместо HTTPS

**Проблема.** API и документы отдаются по `http://186.246.12.170:3000`.
Google Play в Data Safety требует заявить шифрование при передаче; открытый http
этому не соответствует. Кроме того, политика конфиденциальности по http-ссылке
часто отклоняется.

**Что сделать.**
1. Привязать домен к VPS.
2. Выпустить сертификат Let's Encrypt (`certbot --nginx`).
3. В nginx настроить проксирование `/api/` и `/ws` на 3000 c TLS.
4. В `app/src/main/java/com/nexory/app/NexoryConfig.kt` заменить схему на `https`
   (WebSocket-адрес выведется автоматически: `wss`).
5. Удалить блок `<domain-config>` из `res/xml/network_security_config.xml`.
6. В Data Safety ответить «данные шифруются при передаче» — **да**.

Для RuStore http, как правило, проходит, поэтому первый релиз можно выпустить и так,
но до Google Play пункт обязателен.
